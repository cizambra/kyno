When is Kyno useful?

When several agents need shared direction, when priorities change during a run, or when your integration needs to record which direction a step received. For a short workflow whose direction is fixed, an existing prompt or file may meet your needs.

How does direction relate to a system prompt?

A system prompt can carry direction alongside instructions for a model call. Kyno manages the direction's identity, current version, and history independently. An adapter retrieves a version and supplies it in the model context; the prompt carries that copy. A fixed prompt may be sufficient for a short workflow with unchanging direction.

Which frameworks does Kyno support?

Kyno ships integrations for CrewAI and LangGraph. CrewAI receives direction through a before-model-call hook. LangGraph receives it in graph state; your model-calling node includes it in the model input. For other frameworks or languages, use the Python SDK or build an adapter through MCP.

Do I need to run a separate server?

No. Kyno can run embedded in your Python application or as a separate service over stdio or HTTP. Start with SQLite; PostgreSQL and MySQL are also supported. See the embedded setup and deployment guidance.

Can I keep my constitution in Git?

Yes. Git provides authoring, review, and file history. Kyno provides the runtime read interface and versioned direction that integrations consume. After review, apply the approved file from your Kyno workspace:

kyno apply constitution.yaml --note "Reviewed support priorities"

To apply through a configured remote profile, add --remote:

kyno apply constitution.yaml --remote \
  --note "Reviewed support priorities"

Kyno does not synchronize Git changes automatically. See the Git review and apply workflow.

Can agents change the mission or principles?

Only if their application has write access. The shipped adapters only read direction. Give agent applications read-only HTTP tokens, and keep write credentials with operators or trusted deployment jobs. Local CLI, stdio, and embedded access use the host process's permissions. See who should hold write access.

Agents can propose changes if your application provides a review channel. A proposal does not change active direction; an authorized operator or deployment job must apply an accepted edit. Kyno does not manage proposal review. See proposing constitutional changes.

Is Kyno an orchestrator?

No. Your framework continues scheduling tasks, invoking tools, and running agents. Kyno stores and delivers direction through MCP. Its adapters connect that direction to the workflow you already have; updates do not rewrite tasks or replan the workflow.

Is Kyno an AI governance system?

No. Kyno supplies versioned mission and principles for agents to exercise judgment. You can use it with or without AI governance tools. When governance boundaries are present, they define what an agent may do; Kyno supplies direction for judging how to pursue the intended outcome within those boundaries. It complements governance tools and does not replace them or establish that an agent's decisions are safe or aligned.

Does Kyno prevent drift or guarantee alignment?

No. Kyno stores versioned direction and its adapters pull it before work proceeds. Pulls can fail, and an agent can receive the right principles and still misinterpret them or make a bad decision. Claims about improved behavior require evidence from the actual integration and task.

What happens if a pull fails?

By default, the binder logs the failure and uses cached direction. If it has never fetched direction, it supplies empty version 0. Configure PullPolicy(fail_closed=True) to raise an error instead. This policy applies to direction reads: an initial kyno.connect() failure raises an error before a binder is available. See connection troubleshooting.

Current direction depends on a successful pull; an update committed after that read becomes available on a later pull.

Do I need a verifier?

Verification is optional, but recommended. Your application can check outputs against their supplied direction using its own checks or an independent verifier. Those assessments can feed back into the running workflow, giving your application a chance to correct course and improve outcomes before the run ends. Your application chooses whether to continue, retry, or ask a person to review the result. Kyno supplies direction; it does not run verification or decide what happens next.
