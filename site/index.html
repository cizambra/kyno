Your agents are playing a bad telephone game.

Kyno holds one versioned source of direction, and your agents pull it before every step. Change the mission once and the very next step runs on it.

$ pip install kyno
Star on GitHub

The problem

Stale direction is worse than no direction

When goals change, an agent holding the old copy keeps working toward it, and your quality checks push finished work back toward the obsolete goal.

Kyno removes the copy: one versioned store, pulled before every step, subscribers notified the moment it changes.

How it works

Pull, push, and version-stamped answers

Pull before every step

An agent binds the direction in force at its step boundary. This block is what lands in its context before the step runs.

[kyno:direction constitution=default version=1]
Mission: To help organizations keep
multi-agent systems coherent.
Principles:
- Coherence is the goal
- Stay simple, stay nimble
- We don't judge
…
Recent changes:
- Kyno adopts its own constitution

Push when it changes

Subscribers hear the moment a new version is appended. The notification carries no content; the next pull does.

{
  "jsonrpc": "2.0",
  "method": "notifications/resources/updated",
  "params": {
    "uri": "kyno://constitution/current"
  }
}

Every answer carries its version

Ask what changed since the version you knew, and get the delta. A transcript can always say which direction each step served.

get_changes_since(known_version=0)
→ {
  "current_version": 1,
  "changed": true,
  "mission": "To help organizations keep
    multi-agent systems coherent.",
  …
}

Quick start

Running in a minute

pip install kyno
kyno init-db
kyno set --mission "Ship a lending product people trust" \
         --note "initial constitution"
kyno current
kyno serve --transport stdio    # or --transport http
